# MeetSieve Content Design

## 1. 语气

文案应直接、平静、准确。优先说明当前事实、影响和可执行动作，不渲染焦虑，不用
营销口吻掩盖失败。

推荐结构：

```text
发生了什么 → 哪些内容仍然安全 → 用户现在能做什么
```

示例：

> 实时转写暂不可用。录音仍在本地保存。你可以仅录音继续，或返回设置检查凭证。

## 2. 固定术语

| 使用               | 不要使用                       |
| ------------------ | ------------------------------ |
| 会议工作目录       | 数据目录、项目目录、会议文件夹 |
| 实时转写           | 面向用户直接写 ASR             |
| 补转写             | 二次识别、后处理识别           |
| 原始记录           | 原始纪要、Transcript           |
| 会议纪要           | 总结、AI 报告                  |
| 会议消息           | 聊天、群聊                     |
| 临时显示名称       | 游客账号、选择成员身份         |
| 修改工作目录       | 迁移工作目录、搬迁工作区       |
| 安装位置           | 程序工作目录、数据安装位置     |
| 创建桌面快捷方式   | 添加到桌面                     |
| 允许专用网络访问   | 开放网络                       |
| MeetSieve 正在运行 | 文件被占用                     |
| 请先退出 MeetSieve | 强制结束进程                   |
| 保留会议工作目录   | 保留全部内容                   |
| 仅录音继续         | 降级运行、忽略错误             |
| 永久删除           | 清理、移除                     |
| 保留当前记录       | 保留实时结果                   |
| 使用文件补转写     | 用离线结果覆盖                 |
| 保存修改           | 确认版本、恢复版本             |

技术诊断、日志和开发工具可以在“实时转写”后补充 `ASR`，用户主界面不以缩写
代替业务名词。

火山新版凭证在用户界面统一写作 `APP Key`，不写作 `API Key`、`App Key` 或“访问令牌”。
历史配置提示统一使用“旧版凭证已停用，请配置 APP Key”；“已保存”只表示本地已保存非空
凭证，不表示连接、真实音频或补转写成功。

“修改工作目录”只表示保存新的目录路径。MeetSieve 不承诺复制、移动、合并或删除
目录；需要搬移现有数据时，文案应明确要求用户先退出应用，再通过操作系统复制完整
工作目录。

安装、升级和卸载使用以下固定文案：

- 无效安装位置：`请选择新的空目录，或已有的 MeetSieve 安装目录。`
- 应用正在运行：`MeetSieve 正在运行。请先结束正在进行的会议并退出应用，然后重试。`
- 卸载完成：`MeetSieve 已卸载。会议工作目录、本机配置和日志均已保留。`
- 存在未知文件：`安装目录中存在不属于 MeetSieve 的文件，因此该目录已保留。`

## 3. 状态动词

严格区分：

- 等待：任务尚未开始；
- 正在/处理中：任务已经开始但没有完成；
- 已完成/已保存：最终结果已经验证；
- 可重试：上次处理失败且存在安全重试路径；
- 已停止：系统主动或正常结束，不等于失败；
- 暂不可用：外部依赖失败但核心功能可继续；
- 失败：目标没有完成，必须说明影响。

“任务已开始”不能写成“操作成功”。“本地已保存”不能覆盖 Codex 同步失败或
补转写未完成。

## 4. 按钮

- 使用明确动词和对象：`重试补转写`、`结束并保存`、`永久删除会议`。
- 避免：`确定`、`处理`、`继续`、`完成` 等脱离上下文的模糊词。
- 主按钮通常 2–6 个汉字；过长时先优化文案，不允许桌面按钮换行。
- Cancel 根据上下文写成 `继续会议`、`稍后处理`、`返回`，不要统一成“取消”。
- 危险按钮必须明确对象，不能只有“删除”。

## 5. 错误

用户可见错误包含：

1. 简短标题；
2. 对本地录音或数据的影响；
3. 可执行恢复动作；
4. 必要时提供已脱敏诊断编号。

不显示本地完整敏感路径、SQL、凭证、堆栈或厂商原始错误。

## 6. 格式

- 会议号：等宽，例如 `20260731-A7K2-03`；
- 时间点：`00:23:08`；
- 时间范围：`00:37:14–00:39:02`，使用半角冒号和连接号；
- 日期：列表使用相对日期并补时间；详情使用完整日期；
- 文件大小：`2.8 MB`、`500 MB`；
- Windows 路径：`D:\MeetSieve`；
- macOS 路径：`/Users/name/MeetSieve`；
- URL、命令、版本和 ID：等宽字体；
- 人数：`4 位成员`、`3 人在线`，不要混用“个用户”。

## 7. AI 内容

- 问题标记为 `AI 问题`；
- 回答标记为 `AI 回答`；
- AI 回答不能使用“会议结论”样式；
- 被取消或失败的问题要保留状态，但 partial 回答不进入正式记录；
- 处理中写 `AI 正在回答`，超过 30 秒写 `AI 处理时间较长`；
- Codex 失败写 `Codex 暂不可用`，同时说明录音、实时转写和本地保存是否继续；
- 会议详情的接续入口固定为 `用 Codex 继续`；有 thread 时写 `恢复原对话`，无 thread 时明确仍可 `从会议文件继续`；
- 文件接续方式固定为 `接续提示词` 与 `终端命令`；复制动作使用 `复制恢复命令`、`复制提示词` 和 `复制终端命令`，复制失败写 `无法写入剪贴板，请手动复制…`；
- 接续 Modal 右下固定操作为 `关闭`，不因加载或失败改为不可用；
- 成功最终回答明确提示会公开到局域网访客页，问题、partial、失败和取消不公开；
- 原生审批按钮固定为 `拒绝` 和 `允许本次操作`，不使用模糊的“确定”或“始终允许”；
- 纪要未生成时使用 `生成会议纪要`，已有纪要时直接展示正文并使用 `编辑` 进入源码模式；
- 收尾处理中写明具体步骤，不使用“正在处理会议”概括本地保存和外部同步；
- 收尾失败先说明完整录音尚未完成，再说明录音分片和会议事件是否仍安全；
- 补转写冲突固定使用 `保留当前记录`、`使用文件补转写`、`手动修改`；
- 会议纪要设置说明用户可调整内容重点、详略和表达方式；同时明确 MeetSieve 固定处理事实边界、格式、来源引用和转写缺口。

## 8. 会议事件

- 原始记录优先显示正式参会人名称；存在单场未知聚类时显示“未知说话人 1、2……”。
- 尚未关联正式成员但 ASR 已在当前会话内稳定归并时显示“说话人 1、2……”；没有稳定轨道时显示“未识别说话人”。不得展示 `speaker-1` 等 ASR 内部标签。
- 用户界面不展示 `utterance.final`、`message.created`、`resource.created`、`ai.answer` 等内部事件类型。
- 事件类型分别使用“会议消息”“附件”“链接”“AI 问题”“AI 回答”“转写缺口”等中文业务名称。
- 原始记录使用会议内时间定位事件；`seq` 只用于排序、分页和追溯，不作为默认用户文案。

## 9. 录音与隐私

- 录音状态必须显式可见；
- 不增加独立首次知情确认流程；安装说明只提醒：`使用录音功能前，请确认已按适用规则告知参会者。`；
- LAN 使用 HTTP 时要提示不要在公共网络使用；
- 附件属于不可信输入的安全规则不使用恐吓式文案。
