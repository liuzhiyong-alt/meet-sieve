# MeetSieve 设计语言

## 1. 产品气质

MeetSieve 是会议事实记录工具，不是会议展示工具。界面的首要责任是让用户相信：

1. 录音正在进行；
2. 数据正在可靠落盘；
3. 外部依赖失败不会破坏本地事实；
4. 失败和未完成状态不会被伪装成成功；
5. 用户始终知道下一步能做什么。

对应的视觉语言是安静、可靠、克制和状态优先。设计变化度低，动效强度低，信息
密度中等偏高。

## 2. 从当前 UI 提炼出的特征

- 白色工作画布、浅灰页面背景、近白侧栏形成三级浅色表面。
- `#1d1d1f` 近黑承担正文和高对比主导航，避免纯黑大面积压迫。
- `#0071e3` 只用于主要操作、选中和焦点。
- 状态色面积很小，主要出现在圆点、胶囊标签、提示背景和危险操作。
- 卡片依靠细边框和留白分组，阴影只用于 Modal、Toast 等真正浮层。
- 页面标题明显，但不使用 Apple 营销页的大型 Hero。
- 时间、会议号、路径和运行指标使用等宽字体，帮助快速核对。
- 按钮以胶囊形为主，卡片、字段和面板使用分级圆角。
- 会中页面通过状态台、计时器、音频电平和统一时间线建立产品识别度。

## 3. Apple 基础如何使用

Apple 只提供以下基础参考：

- 中性画布与单一蓝色强调；
- Display/Text 字体职责分离；
- 紧凑标题、舒适正文；
- 依靠表面和边框而不是重阴影建立层次；
- 胶囊按钮与有目的的圆角层级；
- 快速减速、无弹跳的微动效；
- 控件视觉克制，让内容和状态成为前景。

以下 Apple 特征不进入 MeetSieve：

- 黑白电影式营销章节；
- 56px、80px Hero；
- 商品图片、轮播和配置器叙事；
- 100px 级营销章节间距；
- 为视觉戏剧性设计的渐变、全屏媒体和滚动动画；
- Apple 平台独占的 SF Symbols 作为跨平台图标来源。

## 4. 信息层级

同一页面的优先级从高到低：

1. 当前是否在录音、保存或执行不可逆操作；
2. 是否存在阻塞用户的失败；
3. 页面主任务和唯一主要操作；
4. 会议内容、成员、消息和处理结果；
5. 外部依赖状态与辅助操作；
6. 元数据、路径、时间和解释性帮助。

每个页面原则上只保留一个主按钮。多个动作同等突出会削弱状态判断。

## 5. 表面与容器

- 页面背景用于衬托应用画布，不承载内容。
- 侧栏、状态台和强调卡片使用近白表面，不使用彩色大底。
- 普通内容优先使用留白、列表分隔线或一层卡片，不叠套多层卡片。
- 浮层仅用于需要暂停当前任务、二次确认或补充少量输入的场景。
- 长流程、复杂校对和恢复任务不应塞入 Modal，应先补页面设计。

## 6. 状态优先

- 录音红色只表示真实录音或永久危险操作，不能作为普通品牌强调色。
- 绿色只表示已验证健康或完成，不能表示“任务已提交”。
- 黄色表示可以继续但需要关注，必须同时提供文案。
- 灰色表示空闲、未知、停止或非阻塞信息。
- 蓝色表示用户动作、焦点和 AI 参与，不表示成功。
- 独立状态轴不能合并成模糊的“全部正常”或“会议已保存”。

## 7. 动效

动效必须说明系统正在发生什么：

- 录音脉冲：表达录音持续进行；
- 音频电平：表达输入存在；
- 进度条：表达有确定阶段或连续进度；
- 按钮 Busy：阻止重复提交；
- Toast：表达短暂且不需要后续处理的结果。

禁止弹跳、无意义循环、装饰性悬浮、长距离飞入和大面积视差。尊重减少动态效果
偏好。

## 8. Do

- 优先复用现有 token、基础组件和产品模式。
- 让状态文案与颜色同时表达含义。
- 使用真实业务名词和明确动作。
- 把失败原因放在发生问题的上下文附近。
- 保持主要操作唯一、危险操作克制但明确。
- 新状态优先组合 `Status + Notice + Progress + Button`。

## 9. Don't

- 不直接复制 Apple 官网页面或营销组件。
- 不引入第二强调色、渐变、玻璃拟态或重阴影。
- 不为“更丰富”给现有纯文字导航随意加图标。
- 不使用 Emoji、Unicode 符号或混合图标库代替正式图标。
- 不把复杂流程塞进过小弹窗。
- 不在业务页面写临时颜色、圆角和阴影覆盖基础组件。
- 不把处理中、部分成功或外部同步失败写成完整成功。
- 不自行增加深色模式。
