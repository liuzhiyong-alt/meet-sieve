## 1. 使用规则

本文件只管理大步骤，不代替每个 Step 的需求确认、技术设计、开发计划和验收记录。

后续执行必须遵守：

1. 同一时间只能有一个进行中的 Step。
2. 当前 Step 未达到退出条件、未记录验证证据、未由用户确认前，不进入下一 Step。
3. 开始每个 Step 前，重新读取本文件和《技术方案》，只针对当前 Step 走一遍设计与开发流程。
4. 每个 Step 的详细方案不得擅自改变《技术方案》的已确认范围。
5. 如需降级、删减或跨 Step 调整，必须先说明原因、影响和替代方案，并取得用户确认。
6. 单元测试中的 fake/mock 只用于隔离依赖，不能用于宣称真实音频、火山 ASR、Codex、声纹、安装包或跨平台链路已经通过。
7. 每完成一个 Step，更新本文件中的状态、完成日期、详细文档链接、验证证据和遗留风险。
8. 发现后续 Step 的问题时可以记录，但除非它阻塞当前 Step，不提前开发后续业务。
9. 紧急修复已完成 Step 的缺陷时，必须记录回溯原因并重新执行受影响的完成门。
10. “完成”表示满足该 Step 的退出条件，不以代码量、页面数量或编译成功代替验收。

## 4. Step 0：项目初始化与工程基础

### 4.1 目标

在不开发具体会议业务的前提下，完成技术选型落锁、工程骨架、基础组件、质量门禁和最小真实 smoke 验证，使后续业务都在同一套稳定结构上开发。

Step 0 结束后，不允许后续 Step 再随意替换 Wails、依赖注入、配置、日志、错误、数据库迁移、测试目录或构建入口。

详细实施顺序见：[Step 0 项目初始化与工程基础实施计划](../plan/Step0-项目初始化与工程基础实施计划.md)。

完成门证据见：[Step 0 验证记录](Step0-验证记录.md)。自动化与真实 smoke
均已通过，用户已于 2026-07-31 确认验收，Step 0 已完成。

### 4.2 范围

#### 项目与工具链

- 初始化 Git 仓库和基础忽略规则；
- 使用 mise 固定 Go 和 Node 版本；
- 初始化 Wails v2 + Vue 3 + TypeScript + Vite；
- 锁定前端和 Go 依赖；
- 定义版本、commit、构建环境等 ldflags；
- 建立 Makefile 的统一开发、测试、构建和打包入口。

#### 技术选型落锁

需要形成依赖清单及简短 ADR，至少覆盖：

- Wails v2 稳定版本；
- Vue Router、Pinia；
- Uber Fx；
- Gin；
- GORM、SQLite driver、`golang-migrate`；
- Zap；
- 统一错误所需 errors 库；
- `malgo` / miniaudio；
- ONNX Runtime Go binding 与动态库携带方式；
- Codex app-server JSON-RPC 客户端方式；
- Windows CGO 交叉编译工具链；
- NSIS；
- 测试、lint 和 Markdown/OpenAPI 检查工具。

选型记录必须写明：

- 采用项及准确版本；
- 使用位置；
- 是否包含 CGO 或动态库；
- macOS arm64、Windows amd64 支持情况；
- 许可证；
- 被否决的主要候选及原因；
- 后续替换触发条件。

#### 工程骨架

建立《技术方案》定义的目录边界：

```text
cmd/
configs/
migrations/
models/
frontend/
internal/app/
internal/domain/
internal/service/
internal/port/
internal/adapter/
internal/infra/
internal/transport/wails/
internal/transport/http/
tests/unit/
tests/integration/
tests/contract/
tests/e2e/
build/
```

空目录不为凑结构而创建；只有存在说明文件、基础实现或测试入口时才落盘。

#### 基础组件

- Fx composition root、模块聚合和 lifecycle；
- 严格解析、校验并 `go:embed` 的 `config.yaml`；
- 结构化日志、轮转和脱敏基础；
- `AppError`、稳定错误码、cause、op 和错误转换；
- GORM SQLite 连接工厂和 PRAGMA；
- `golang-migrate` 内嵌 migration runner；
- repository 和事务抽象的最小边界；
- Gin Engine、统一错误中间件、Recovery、访问日志和路由注册机制；
- Wails binding 注册、前端调用结果和事件 envelope；
- 文件原子写、路径校验、哈希等通用文件能力；
- Clock、ID generator 等可测试基础依赖；
- 应用健康状态与启动失败展示的最小壳。

#### Port 定义

只定义技术方案已经确认需要替换边界的 port，不提前实现业务：

- `AudioCapture`；
- `RealtimeTranscriber`；
- `FileTranscriber`；
- `VoiceEncoder`；
- `AgentProvider`；
- 工作目录文件存储边界。

接口使用业务语义，不泄漏火山、ONNX、Codex JSON-RPC 或平台 API 类型。

#### 最小真实 smoke

smoke 只验证选型可行，不实现会议流程：

- Wails 壳应用在当前 macOS arm64 启动；
- Wails binding 调用和 event 往返；
- Fx 启动、正常停止和启动失败清理；
- SQLite CGO 打开、migration、WAL 和外键；
- `malgo` 枚举本机录音设备；
- ONNX Runtime 动态库能被加载，模型选择留在 Step 2；
- 本机 Codex app-server 完成 `initialize/initialized` 握手后退出；
- 最小 Windows amd64 GUI 可执行文件完成 CGO 交叉编译；
- 最小 NSIS 安装程序可以生成；
- Windows PE 使用 GUI subsystem，不产生控制台窗口。

### 4.5 退出条件

### 5.3 退出条件

- 工作目录丢失时不静默创建空库；
- 手动复制完整目录后可通过修改路径继续使用原数据；
- 正常设置修改在下次启动生效；
- 安装目录及其内部不能作为工作目录；
- 重装后重新选择已有工作目录时设备码不变；
- `000001` 指纹不匹配时不猜测升级，`000002` 半完成库不会被安装；
- schema migration 失败时原库和备份可用；

- 设置与工作目录不可用页面按 `docs/UI` 中的现有设计还原；缺失状态遵循
  `docs/style/meet-sieve` 设计约束补齐并保持可操作。
