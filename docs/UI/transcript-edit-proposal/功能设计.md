# 原始记录编辑功能设计提案

> 状态：待用户审核。本文只定义产品功能与交互，不修改技术方案、接口、数据库或正式页面金标。

## 1. 目标

把现有“选择片段后在右侧逐条校对”的工作台，收敛为更接近文档编辑的操作：

1. 在会议详情中直接找到“编辑原始记录”入口；
2. 在编辑页按需设置本场未知说话人与参会人的对应；
3. 在记录正文中直接修改文字；
4. 每段记录都可以就地播放对应录音；
5. 所有未保存修改通过一个页面级按钮统一保存。

## 2. 非目标

- 本轮不修改技术方案、数据库、接口或正式前端代码；
- 不把校对设置为生成会议纪要的前置条件；
- 不自动把人工说话人修改加入永久声纹；
- 不把 ASR 内部的 `speaker_0`、`speaker_1` 暴露给用户；
- 不设计时间边界拖拽、音频剪辑或多人同时编辑。

## 3. 页面与入口

### 3.1 会议详情

“原始记录”Tab 默认用于只读浏览，页面提供：

- `编辑原始记录` 主入口；
- 每段记录的播放操作；
- 当前说话人处理状态，例如“2 位未知说话人待确认”；
- 当前文字是否已经人工修改；
- 原始记录分页能力保持不变。

会议结束后进入会议详情。用户可以直接生成纪要，也可以按需进入编辑页。

### 3.2 原始记录编辑页

页面按从全局到局部的顺序组织：

1. 页面说明与会议信息；
2. 可选的本场说话人对应关系；
3. 可直接编辑的原始记录列表；
4. 记录标题行内的统一保存按钮。

## 4. 说话人处理

### 4.1 默认按本场未知说话人批量对应

页面只展示本场聚类后的名称：

- 未知说话人 1；
- 未知说话人 2；
- 未知说话人 3。

每个未知说话人显示影响片段数，并允许选择：

- 本场正式参会人；
- 本场临时参会人；
- 保持未知。

选择参会人后，属于该未知说话人的所有片段立即更新预览。修改在点击“保存修改”后统一保存。

### 4.2 单段说话人

每条记录直接显示当前说话人的下拉框，不再提供“修改本段说话人”按钮和展开面板。不修改时保持当前值；选择其他参会人时只覆盖本段，不改变同一未知说话人的其他片段。

## 5. 文字编辑

- 正文始终使用与记录同宽的输入框，不再区分阅读态和编辑态；
- 鼠标点击输入框即可修改；
- 撤销使用操作系统标准的 `Ctrl+Z` 或 `Command+Z`；
- 输入框随内容自动增高，短内容保持紧凑；
- 修改后的记录显示“文字已修改”；

## 6. 播放

- 每条有可用录音的记录，在时间右侧显示低强调的 `播放`；
- 文字大小和颜色与同行元数据协调，点击区域仍满足桌面按钮尺寸；
- 同一时间只播放一个片段；
- 播放时按钮显示 `暂停`，并在记录中显示播放状态；
- 录音已删除、缺失或校验失败时禁用播放，并在该记录附近解释原因。

## 7. 保存与离开

### 7.1 页面级保存

“原始记录”标题行只显示 `保存修改` 主按钮。页面滚动到该区域后，标题行固定在 Titlebar 下方，继续滚动时只移动记录内容。

没有修改时按钮禁用。保存中禁止重复提交。保存完成后显示“原始记录已刷新”。

### 7.2 未保存离开

存在未保存修改时离开页面，弹窗提供：

- `继续编辑`；
- `放弃未保存更改`；
- `保存并返回会议详情`。

## 8. 冲突与失败状态

- 当前记录已被其他后台结果更新时，在对应记录中显示持续警告，用户选择保留当前文字或重新载入；
- 修改已经保存到本地，但原始记录文件刷新失败时，保留已保存事实，并提供重试刷新；
- 批量说话人对应与单段例外冲突时，明确显示“本段使用单独指定”；
- 任何失败都不把已经安全保存的数据表述为未保存。

## 9. 本轮 HTML 审核重点

请重点审核：

1. 会议详情中的编辑入口是否足够明显；
2. 说话人对应关系放在记录列表顶部是否自然；
3. 单列内联编辑是否比原双栏工作台更轻；
4. 每段播放按钮的位置和视觉强度是否合适；
5. 标题行吸顶和保存按钮的位置是否自然。
