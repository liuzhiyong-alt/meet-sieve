# 会意（MeetSieve）用户旅程

> 状态：已确认  
> 确认日期：2026-07-28

## 1. 旅程原则

- 只需要录音人安装和操作会意；
- 其他参会者不强制进入局域网页面；
- 会议中默认安静记录，不要求录音人持续操作；
- AI 只有在被唤醒时才明显参与；
- 所有会议数据优先安全保存到录音人的本地目录；
- 会议纪要、校对和 Codex 整理均为可选步骤；
- 本地会议记录是事实源，不依赖某个 Codex 会话持续存在。

## 2. 角色

### 录音人

主要操作者和本地数据持有者，负责开始和结束录音，以及按需发起会后整理。

### 其他参会者

正常参与线下讨论。可以选择扫码进入局域网页面，查看会议消息历史并发送文字、链接和文件。

### 会意本地系统

负责录音、转写、说话人识别、时间线、局域网服务、文件保存和会议恢复。

### Codex

会议中按需参与讨论，会后执行整理和上传流程。Codex 可以按会议号重新读取本地会议，不依赖原会话。

## 3. 主旅程

### 阶段 0：首次配置

录音人：

1. 指定工作目录，默认自动补上 `ai-meetings`，允许修改；
2. 配置自己的信息、ASR 平台和录音设备；
3. 按需建立常用小组，配置成员、声纹和默认项目目录。

本地系统：

- 将设置、常用小组和声纹向量保存到本地 SQLite。

### 阶段 1：准备会议

录音人：

1. 选择常用小组，或直接添加人员；
2. 勾选本场实际参会人；
3. 快速确认会议号、主题、项目目录和录音设备；
4. 开始会议。

约束：

- 会议号自动生成并允许修改；
- 主题非必填；
- 项目目录默认继承常用小组，允许本场覆盖。

本地系统：

- 创建会议目录和本地数据库记录；
- 准备录音、转写和可恢复状态；
- 启动本场局域网访问入口。

### 阶段 2：安静记录

录音人：

- 只需要确认正在录音、时长、音频和转写状态正常；
- 之后继续正常参与讨论，不需要持续盯着软件。

其他参会者：

- 正常参加线下讨论；
- 不注册账号；
- 会意不采集其个人设备音频。

本地系统：

- 持续录音和增量转写；
- 识别说话人；
- 将转写写入会议时间线；
- 持续保存可以恢复的本地状态。

### 阶段 3：补充资料与 AI 参与

录音人：

- 按需展示二维码或局域网短地址；
- 需要 AI 参与时说出唤醒词“会来事儿”，然后提出问题。

其他参会者：

1. 可选扫码进入本场会议；
2. 从已配置参会人中选择自己的姓名；
3. 查看本场会议消息历史；
4. 发送文字、链接或文件。

本地系统：

- 将转写、访客消息、链接、文件和 AI 问答统一写入会议时间线；
- 为本次 AI 请求组织会议摘要、相关原文、最近增量和附件上下文。

Codex：

- 根据本次请求参与讨论；
- 将回答写回会议时间线，成为会议原始记录的一部分。

### 阶段 4：结束与落盘

录音人：

1. 手动结束会议；
2. 等待保存完成；
3. 明确看到录音、转写、消息和附件均已保存。

本地系统：

- 完成最终转写；
- 生成或更新会议原始记录；
- 若存在未完成任务或保存异常，必须明确显示并提供处理入口。

### 阶段 5：整理与衔接

录音人可以选择：

- 一键生成会议纪要；
- 在会意内校对，也可以跳过校对；
- 使用 Codex 继续整理、确认关键业务规则并上传到共享位置；
- 以后通过会议号重新打开会议。

本地系统：

- 原始记录始终存在；
- 会议纪要草稿仅在用户触发后生成；
- 按会议号长期提供本地读取能力。

Codex：

- 可以从新会话读取指定会议号；
- 恢复会议原文、消息、附件和已有纪要；
- 执行后续整理与上传流程。

## 4. 核心结果

开会时只需要一个人负责开始和结束录音。其他人进入局域网页面是可选行为。会议结束后，数据首先安全落盘；生成纪要、校对和 Codex 工作流都不会阻塞会议保存。
